# Task 4 问题解决思路：Task 3 子图像二值化

## 1. 任务要求

把 Task 3 提取的 `HD44780A00` 子图像转换为 binary image，并展示中间结果；
若尝试多种方案，需说明最终选择及理由。

## 2. 输入与难点

- 输入：`task_3/outputs/task3_subimage.png`（899×148 增强灰度子图）。
- 难点：背景环状纹理很亮（5×5 平滑后纯背景 p99 ≈ 140），全局单一阈值无法同时把笔画与纹理分开。

## 3. 比较的三种方案（阈值与连通域均用 `common.py` 自实现）

1. **全局 Otsu**：`T*=125`，把 34.0% 像素判为前景，产生 296 个连通分量，字符反而粘连成 7 组——失败。
2. **5×5 平滑 + Otsu + 3×3 开运算**：分量降到 32，但字符仍粘连为 7 组，最大斑点存活——仍不可用。
3. **41×41 局部自适应均值阈值（选定）**：

   ```text
   T(x,y) = mean_41(x,y) + 25
   B(x,y) = I(x,y) > T(x,y)
   ```

   先 5×5 平滑，再标记“比局部均值亮 25 灰度级”的像素，恰好适合“亮字符 + 暗纹理背景”。

## 4. 结果与验证

选定方案：前景 30.72%、共 126 个分量，其中 **恰好 10 个面积 ≥500px** 的分量，按 x 坐标从左到右一一对应 `H D 4 4 7 8 0 A 0 0`；其余 116 个噪声分量面积 ≤224px，留给 Task 6 用面积准则过滤。

## 5. 输出文件（`task_4/outputs/`）

- `task4_binary.png`：**最终选定的二值图**（传给 Task 5/6）；
- `task4_binary_otsu.png`、`task4_binary_otsu_cleaned.png`：两个对比方案；
- `task4_comparison.png`：子图 + 三种方案对比；
- `task4_metrics.csv`、`task4_thresholds.json`：指标与参数元数据。

## 6. 风险与注意

- 自适应窗口（41）必须明显大于字符笔画宽度（约 10–20px）而小于背景纹理尺度，才能让局部均值代表“局部背景”。
- offset=+25 是经验值：太小会引入纹理噪声，太大会把细笔画挖断；换图后应重新扫窗口/offset。
- 若图像光照更均匀，全局 Otsu + 形态学也可能足够，不必一律用自适应阈值。
